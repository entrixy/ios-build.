# Скриншоты всех этапов Entrixy

Требование пользователя 12.11.2026: полностью готовое приложение для App Store и
скриншоты каждого этапа, чтобы проверить весь пользовательский путь.

Изображения снимаются с работающего приложения через `simctl io screenshot`,
не рисуются и не заменяются макетами. Capture review JSON содержит source_sha, SHA-256,
модель iPhone и runtime; публичный manifest сохраняет общий source и хеши PNG. До визуального просмотра новых кадров статус pending.
Снимок интерфейса не подтверждает физическое открытие/Face ID/работу в фоне.

## Bluetooth: привязка и ручной импульс владельца (source only)

Добавлены `ble-scan`, `ble-uncertain`, `ble-paired`, `ble-registered`,
`ble-owner-confirm`, `ble-owner-result`, `ble-owner-unknown`, `ble-owner-journal`.
Обычные модели/экраны работают с явно обозначенным программным BLE-контроллером;
реальные X25519/HMAC, сохранение до записи, проверка объявления и одна FIRE-запись.
TIME-result не считается FIRE-result, потерянный ответ остаётся неизвестным.
Журнал появляется от фактического выполнения тестовой попытки, не из заготовки.

Матрица теперь **77×2×2=308 ожидаемых PNG**. Ни эти кадры, ни Apple build/native
execution текущего кода пока не получены. Симуляторные кадры не проверят разрешение
CoreBluetooth, радио, GATT/MTU, режим pair и реальное оборудование. Гостевые BLE
expiry/renew/revoke ещё требуют отдельного переноса и проверки.

Guest BLE добавляет `ble-guest-confirm`, `ble-guest-result`, `ble-guest-expired`,
`ble-guest-unknown`, `ble-guest-journal`: protected offline material, реальная
авторизация AppModel, отдельный TIME и один FIRE с проверкой bytes в software
controller. Истёкший пропуск не отправляет ни TIME, ни FIRE. Новая матрица
**82×2×2=328 ожидаемых PNG**; реальных новых кадров пока нет.

BLE lifecycle добавляет `ble-revoke-pending`, `ble-revoke-applied`,
`ble-revoke-stale`, `ble-renewed`. Software controller проверяет signed23B,
выдаёт отдельные0x40/0x41; неподтверждённое точное решение остаётся unknown.
Продление сохраняет прежнюю ссылку, выполняется обычным pending/edit/readback.
Maintenance не создаёт journal rows. Матрица **86×2×2=344 ожидаемых PNG**;
ни новые native runs, ни новые PNG не получены.

Перед фиксацией кадра macOS Vision проверяет текст нужного экрана. Если вместо
него ещё видна анимация запуска или SpringBoard, повторяется только чтение
снимка того же процесса (до 60 секунд), а не сценарий или команда. Поле
visible_text_verified обязательно для итогового review. Нативные тесты и
съёмка используют разные одноразовые симуляторы; общими могут быть только
проверенные продукты сборки DerivedData, не контейнеры приложения и не Keychain.

Метка тестового стенда занимает отдельную безопасную область и не накладывается
на QR-коды, кнопки или клавиатуру. Формы открываются после подготовки данных
как нижние панели над основной вкладкой; список выданных ключей снимается
в настоящем корне вкладки «Гости», чтобы сохранить её навигацию и логотип.
